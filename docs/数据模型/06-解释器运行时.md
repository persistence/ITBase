# 解释器运行时

职责：在宿主进程里用 Yaegi 装载已发布修订，把 HTTP 扩展路由和内部领域调用接到领域函数 / 接口函数。向解释器只暴露 `itbase.dev/itb` 这一份数据端口。

不负责：草稿与发布事务（见 [源码与发布](05-源码与发布.md)）；目录与 DDL；CEL 规则文本。本模块调用 [数据读写](04-数据读写.md) 完成实际读写。

依赖：已发布修订的源码、路由表，以及数据读写管线。

## 1. 宿主交给解释器的包

解释器里的 import 路径是 `itbase.dev/itb`。符号表用 `yaegi extract` 从宿主这个包生成，随平台二进制发布。解释器启动时只 `Use` 这份符号表，以及第 4 节列出的标准库子集。不加载 Yaegi 自带的全量 `stdlib.Symbols`。

```go
type Actor struct {
    UserID uint64
}

type Input struct {
    Actor Actor
    Body  map[string]any
}

type Output struct {
    Body map[string]any
}

type Request struct {
    Actor   Actor
    Params  map[string]string
    Query   map[string]string
    Body    map[string]any
    Header  map[string]string
}

type Response struct {
    Status int            // 0 视为 200
    Body   map[string]any
}

type Record struct {
    ID        uint64
    CreatedAt string
    UpdatedAt string
    Values    map[string]any
    Links     map[string]any
}

type Write struct {
    Values map[string]any
    Links  map[string]Link
}

type Link struct {
    Op    string
    ID    *uint64
    Items []WriteItem
}

type WriteItem struct {
    ID     uint64
    Values map[string]any
    Links  map[string]Link
}
```

`Write` / `Link` 的字段与 [数据读写](04-数据读写.md) 的 JSON 对应。`Op` 只接受 `set`、`create`、`update`、`remove`、`link`、`unlink`。深度、节点数、环检测仍由宿主写入管线执行。`decimal` 在 `map` 里保持十进制字符串。

`App` 是解释器能碰到的唯一数据端口。它由宿主在每次调用时注入，并且已经绑定当前登录人和当前应用：

```go
func Current(ctx context.Context) (*App, error)

func (a *App) Read(ctx context.Context, entity string, id uint64, expand []string) (Record, error)
func (a *App) Query(ctx context.Context, q Query) ([]Record, error) // 与 HTTP :query 同一计划，含 filter / sort / page / expand
func (a *App) Create(ctx context.Context, entity string, w Write) (Record, error)
func (a *App) Update(ctx context.Context, entity string, id uint64, w Write) (Record, error)
func (a *App) Delete(ctx context.Context, entity string, id uint64) error
func (a *App) Tx(ctx context.Context, fn func(tx *App) error) error

func Eq(field string, value any) Filter
func Ne(field string, value any) Filter
func Gt(field string, value any) Filter
func Lt(field string, value any) Filter
func Gte(field string, value any) Filter
func Lte(field string, value any) Filter
func In(field string, values []any) Filter
func IsNull(field string, null bool) Filter
func Contains(field string, value string) Filter
func StartsWith(field string, value string) Filter
func EndsWith(field string, value string) Filter
func And(parts ...Filter) Filter
func Or(parts ...Filter) Filter

func NewQuery(entity string) Query // 再链式 Where / Order / Limit
```

`Create`、`Update`、`Delete` 进入规则校验、数据读写、权限挂点的同一条管线：只认 `active` 字段和关联，做标准化、必填、CEL、权限挂点，成功才落库。解释器里写不出绕过 CEL 的插入。

`Read` 与 `Query` 同样只暴露 `active` 字段，并进入 [数据读写](04-数据读写.md) 的同一条读管线。`expand` 的元素是导航编码。`Query` 的条件由上面的构造函数拼出，宿主按目录把字段编码映射成列名，使用参数化 SQL。主查询的 `FROM` 只有当前实体表，不写 JOIN；一层导航筛选生成 `IN (SELECT …)` 子查询。关联展示在分页之后按 id 批量加载，不在循环里逐条 `Read`。条件树深度最多 3，叶子最多 20。`size` 默认 50，最大 200。排序字段最多一个，且必须是当前实体列。列表 `expand` 只允许多对一、一对一。

`Tx` 把回调里的读写放进同一个 InnoDB 事务，供「改订单并写订单行」这类动作使用。回调里的 `*App` 复用这个事务。嵌套 `Tx` 返回错误。回调返回错误则回滚。事务外的 `Create` / `Update` / `Delete` 各自独立提交，语义与直接调用数据 API 相同。

`GET` 路由使用的 `*App` 是只读视图：`Create`、`Update`、`Delete`、`Tx` 直接返回错误。

业务错误使用宿主类型，接口层可以原样返回：

```go
func Fail(status int, code, message string) error
```

`status` 取 400、404、409、422。其它错误和解释器 panic 由宿主记成 500，响应不带源码和栈。栈只进服务端日志。

## 2. 解释器池

Yaegi 的一个 `Interpreter` 不能同时执行两次调用。每个已发布修订持有一个池，池大小默认 4，可用配置改为 1–16。池中每个解释器在创建时独立完成：写入虚拟文件系统、`Use` 符号表、`EvalPath` 领域包、`EvalPath` 接口包、断言导出函数。

虚拟文件布局：

```text
src/itbase.app/{appCode}/domain/{filename}
src/itbase.app/{appCode}/api/{filename}
```

一次调用：

1. 从该修订的池中借出一个解释器。池空则等待，最多等该路由的 `timeout_ms`。等不到返回 503。
2. 执行对应函数。宿主在函数返回或 `ctx` 取消后把解释器还回池。
3. 调用发生 panic 时，该解释器不再还回。宿主另起一个补位解释器，从同一份已发布源码重新装载。补位完成前池容量减一。

Yaegi 无法抢占一段不读取 `ctx` 的死循环。借出时间超过 `timeout_ms` 后，宿主取消 `ctx`、结束本次 HTTP 请求，并且同样丢弃该解释器，避免把卡死的实例再借给下一个请求。被丢弃的调用所在 goroutine 会留到那段循环自己结束；因此源码体积和语法由发布检查限制，发布夹具覆盖这条丢弃路径。

`context` 由宿主创建：`WithTimeout(parent, timeout_ms)`。`itb` 的读写在每次数据库往返前尊重取消。

池是本进程的本地缓存。权威修订在 `dm_revision`。多台 `api` 如何发现新发布、失败时是否保留旧池，见 [多实例归属](09-多实例归属.md)。`worker` 角色第一期不建池。

## 3. 新接口如何挂到 HTTP

平台在 GoFrame 上注册一条编译期路由：

```text
ALL /api/v1/ext/{appCode}/{path}
```

`{path}` 承接剩余路径。宿主用已发布修订的路由表做匹配，不把扩展路径注册成可以覆盖 `/api/v1/model` 或 `/api/v1/data` 的路由。

匹配成功后：

1. 解析登录态，得到 `Actor`。未登录返回 401。权限挂点仍包在 `itb.App` 的读写外面；扩展路由本身只要求已登录，不在路由表上再存一套角色。
2. 路径参数写入 `Request.Params`，查询串写入 `Request.Query`，JSON 对象写入 `Request.Body`。体不是 JSON 对象则 400。`GET` 和 `DELETE` 的体必须为空。
3. 从池中借解释器，调用 `api.{handler}`。
4. 返回 `*itb.Fail` 时使用其中的状态码和 `code`、`message`。返回 `Response` 时使用其 `Status` 与 `Body`。

领域函数供以后的工作流在**进程内**调用：同样借池、同样超时、同样把数据端口限制在当前应用。第一期不把 `POST /api/v1/domain/{appCode}/{funcName}` 挂到公网；开放时必须使用服务身份，见 [多实例归属](09-多实例归属.md)。

## 4. 运行时沙箱

标准库子集由宿主逐包导出，不转交 `os`、`net`、`database/sql`、`plugin`、`syscall`、`runtime`、`reflect`、`unsafe`。`fmt` 只导出 `Sprintf`、`Errorf`、`Sprint`。允许的 import 清单见 [源码与发布第 4 节](05-源码与发布.md)。

解释器选项保持 Yaegi 默认的安全边界，不打开访问宿主任意内存的开关。

## 5. 示例

草稿中的领域文件 `domain/order.go`：

```go
package domain

import (
    "context"

    "itbase.dev/itb"
)

func Confirm(ctx context.Context, in itb.Input) (itb.Output, error) {
    app, err := itb.Current(ctx)
    if err != nil {
        return itb.Output{}, err
    }
    id, _ := in.Body["id"].(float64)
    var out itb.Record
    err = app.Tx(ctx, func(tx *itb.App) error {
        rec, err := tx.Update(ctx, "order", uint64(id), itb.Write{
            Values: map[string]any{"status": "confirmed"},
        })
        if err != nil {
            return err
        }
        out = rec
        return nil
    })
    if err != nil {
        return itb.Output{}, err
    }
    return itb.Output{Body: map[string]any{"id": out.ID, "values": out.Values}}, nil
}
```

草稿中的接口文件 `api/order.go`：

```go
package api

import (
    "context"

    "itbase.app/crm/domain"
    "itbase.dev/itb"
)

func ConfirmOrder(ctx context.Context, req itb.Request) (itb.Response, error) {
    out, err := domain.Confirm(ctx, itb.Input{
        Actor: req.Actor,
        Body:  map[string]any{"id": req.Params["id"]},
    })
    if err != nil {
        return itb.Response{}, err
    }
    return itb.Response{Body: out.Body}, nil
}
```

对应草稿路由：`POST` `/orders/{id}:confirm` → `ConfirmOrder`，超时 3000。发布后，客户端调用：

```text
POST /api/v1/ext/crm/orders/41:confirm
```

宿主匹配到该模板，领域函数通过 `tx.Update` 写入。订单上的 CEL 规则失败时，事务回滚，接口得到 422。

JSON 数字进 `map[string]any` 时是 `float64`。领域函数把路径参数转成 `uint64` 时应走 `strconv`，上面的示例为缩短篇幅直接断言。夹具里的正式例子用 `strconv.ParseUint`。

## 6. 本模块完成标准

- 发布成功后立刻用新路由访问到新函数。
- 领域函数里的 `Create` / `Update` 与直接调用 `/api/v1/data` 一样触发 CEL；规则失败时 `Tx` 整单回滚。
- 两个并发请求不会借到同一个解释器。其中一个请求 panic 后，下一个请求仍能完成，池会补回实例。
- 平台启动夹具包含：双包互调、`Tx` 回滚、只读 `GET` 写操作被拒绝、路由不覆盖 `/api/v1/data`。
