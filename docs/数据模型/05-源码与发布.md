# 源码与发布

职责：为每个应用保存一份草稿和一份正在服务的已发布修订。管理领域包、接口包源码与路由表，提供检查和发布。发布只切换流量，不重新编译平台。

不负责：解释器池、HTTP 匹配、宿主符号表（见 [解释器运行时](06-解释器运行时.md)）；实体与字段仍由 [元数据目录](01-元数据目录.md) 和 [结构同步](02-结构同步.md) 管理。

依赖：检查时要能装载源码并断言函数签名，因此与运行时共用同一套 import 白名单和函数签名。扩展代码需要新列、新关联时，先调用结构 API，等字段和关联变为 `active`，再发布引用这些编码的源码。解释器里没有结构 API 客户端。

Yaegi 的版本写进 `go.mod`，与平台使用的 Go 版本一起固定。升级 Yaegi 时先跑通 [解释器运行时](06-解释器运行时.md) 的夹具再换版本。

## 1. 两层代码

每个应用有一份已发布的源码，里面两个 Go 包：

| 包 | 路径 | 职责 |
|---|---|---|
| 领域 | `itbase.app/{appCode}/domain` | 业务动作：读目录内的记录、按数据读写模块的写入图修改当前表和关联表、组织一个事务 |
| 接口 | `itbase.app/{appCode}/api` | 解析 HTTP，调用领域函数，把结果写成响应 |

接口包可以 import 本应用的领域包。领域包不 import 接口包。

领域函数对宿主的入口签名全部相同，方便发布时做类型断言：

```go
func(ctx context.Context, in itb.Input) (itb.Output, error)
```

接口函数签名：

```go
func(ctx context.Context, req itb.Request) (itb.Response, error)
```

包内部可以有自己的结构体和未导出函数。宿主只查找导出的、符合上面签名的函数。

一个应用同时只有一份草稿和一份正在服务的已发布修订。流量只进入已发布修订。

CEL 继续负责能写成布尔表达式的规则。跨多行写入、需要循环聚合或要返回自定义形状的响应时，写领域函数。

## 2. 源码怎么存

```sql
CREATE TABLE dm_revision (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '修订主键',
  app_id       BIGINT UNSIGNED NOT NULL COMMENT '所属应用',
  revision     INT UNSIGNED    NOT NULL COMMENT '修订号，从 1 递增。草稿取已发布最大号加 1',
  phase        VARCHAR(16)     NOT NULL COMMENT 'draft、published、retired',
  edit_version INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '草稿内容版本。每次成功写入加 1，用于 baseEditVersion',
  created_at   DATETIME(3)     NOT NULL COMMENT '创建时间，UTC',
  published_at DATETIME(3)     NULL COMMENT '变为 published 的时间，UTC',
  phase_slot   VARCHAR(64) GENERATED ALWAYS AS (
                 CASE
                   WHEN phase IN ('draft', 'published') THEN CONCAT(phase, ':', app_id)
                   ELSE NULL
                 END
               ) STORED COMMENT '每个应用的 draft 与 published 各一槽。retired 为空，可有多行',
  PRIMARY KEY (id),
  UNIQUE KEY uk_dm_revision (app_id, revision),
  UNIQUE KEY uk_dm_revision_phase_slot (phase_slot),
  KEY idx_dm_revision_phase (app_id, phase)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '应用源码修订。流量只进入 published';

CREATE TABLE dm_file (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '文件主键',
  revision_id BIGINT UNSIGNED NOT NULL COMMENT '所属修订',
  layer       VARCHAR(16)     NOT NULL COMMENT 'domain 或 api',
  filename    VARCHAR(80)     NOT NULL COMMENT '文件名，匹配 ^[a-z][a-z0-9_]{0,39}.go$',
  source      MEDIUMTEXT      NOT NULL COMMENT 'Go 源码。单文件不超过 64KB',
  PRIMARY KEY (id),
  UNIQUE KEY uk_dm_file (revision_id, layer, filename)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '修订中的源码文件';

CREATE TABLE dm_route (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '路由主键',
  revision_id   BIGINT UNSIGNED NOT NULL COMMENT '所属修订',
  method        VARCHAR(8)      NOT NULL COMMENT 'GET、POST、PATCH、DELETE',
  path_template VARCHAR(160)    NOT NULL COMMENT '路径模板。以 / 开头，不含查询串',
  handler       VARCHAR(80)     NOT NULL COMMENT '接口包导出函数名',
  timeout_ms    INT             NOT NULL COMMENT '超时，100–10000，默认 3000',
  PRIMARY KEY (id),
  UNIQUE KEY uk_dm_route (revision_id, method, path_template)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '修订中的扩展路由';
```

`phase`：`draft`、`published`、`retired`。`phase_slot` 把每个应用的 `draft` 和 `published` 收成各一个唯一槽；`retired` 的槽为空，可以有多行。只在文档里写「最多一行」不够，并发 `PUT` 会插出两份草稿。`revision` 从 1 递增。草稿的 `revision` 取「已发布最大号 + 1」。发布事务里先把原先的 `published` 改为 `retired`，再把草稿改为 `published`。顺序反了会撞上 `published` 槽。

`edit_version` 从 0 起。每次成功的文件或路由写入加 1。`PUT` 和 `DELETE` 带上一次读到的 `baseEditVersion`，不匹配返回 409，不覆盖另一位编辑留下的草稿。`GET` 返回当前 `editVersion`。

`layer`：`domain` 或 `api`。`filename` 匹配 `^[a-z][a-z0-9_]{0,39}\.go$`。文件的 `package` 子句必须与 `layer` 一致。

`method`：`GET`、`POST`、`PATCH`、`DELETE`。`handler` 是接口包里的导出函数名，匹配 `^[A-Z][A-Za-z0-9]{0,60}$`。`timeout_ms` 取值 100–10000，默认 3000。

`path_template` 以 `/` 开头，至少一段。每一段是字面量 `^[a-z][a-z0-9_]{0,39}$`，或路径参数 `{name}`，`name` 用同一套编码规则。可以有一段动作后缀，例如 `/orders/{id}:confirm`。模板里禁止 `..`、空段、查询串和完整 URL。同一修订内，方法加模板唯一。

运行时匹配：同一位置上，字面段优先于路径参数。`/orders/new` 与 `/orders/{id}` 同时存在时，`/orders/new` 命中字面模板。两条模板能匹配同一条路径、且字面段数量相同，则 `:check` 失败。例如 `/orders/{id}` 与 `/orders/{no}`。

领域导出函数不单独建表。发布检查时从源码扫出来，装进该修订的解释器。

单文件源码不超过 64KB，一个修订的源码合计不超过 512KB，一个修订最多 32 个文件、32 条路由。

## 3. 草稿与发布

管理接口前缀 `/api/v1/ext-src`，调用方与结构 API 相同。

```text
PUT    /apps/{appCode}/files/{layer}/{filename}
GET    /apps/{appCode}/files/{layer}/{filename}
DELETE /apps/{appCode}/files/{layer}/{filename}

PUT    /apps/{appCode}/routes
GET    /apps/{appCode}/routes

POST   /apps/{appCode}:check
POST   /apps/{appCode}:publish
GET    /apps/{appCode}/published
```

`PUT` 文件和路由都写在草稿上，并带 `baseEditVersion`。没有草稿时，在短事务的同一条连接上取得命名锁 `dm_draft_{appId}`，再从当前已发布修订复制出一份新草稿；还没有任何修订时创建 `revision = 1` 的空草稿。锁与 `phase_slot` 一起保证只会留下一份草稿：后到的事务若撞上唯一键，改为读取已存在的草稿再写入。复制完成后，后续 `PUT` 只改草稿。已发布修订的行不再更新。

`DELETE` 文件只删草稿里的文件。路由 `PUT` 提交整表替换草稿中的路由列表。

`:check` 不切换流量，步骤与发布前半段相同：

1. `go/parser` 解析草稿里的全部文件。
2. 按第 4 节拒绝禁用语法和禁用 import。
3. 在临时解释器里装载领域包、再装载接口包。
4. 每个路由的 `handler` 必须能断言成接口签名。
5. 每个领域包导出的、符合领域签名的函数记入检查结果；不符合签名的导出函数使检查失败。
6. 丢掉临时解释器，不放入运行池。

`:publish` 在检查通过后，同一短事务里先把旧的已发布改为 `retired`，再把草稿改为 `published`。**协议上的完成点是这条事务提交。** 结构上的 `NOT NULL` 不随这次发布一起收紧。要等各 `api` 心跳都装上这份修订，再调用字段接口，见 [结构同步](02-结构同步.md)。本机随后按 [多实例归属](09-多实例归属.md) 建池并在成功后切换；其它 `api` 副本靠轮询 `phase = published` 跟上，不接收这次 HTTP 的进程内通知。换上之前已经取走旧池的请求继续用旧修订，直到请求结束。新请求使用本机当前池。旧池排空后释放。

检查或装载失败时，已发布修订保持原样，接口返回 422，正文带文件名、行号和 Yaegi 或解析器的错误。

进程启动时读取每个应用 `phase = published` 的修订，预建解释器池。之后由 [多实例归属](09-多实例归属.md) 轮询跟上新的已发布行。某个应用装载失败则该应用的扩展接口返回 503，平台自身的 `/api/v1/model` 与 `/api/v1/data` 继续服务。

## 4. 源码限制

发布前用标准库 `go/parser` 与 `go/ast` 走查，出现下列情况则检查失败：

- import 路径不是下面之一：`context`、`errors`、`fmt`、`math`、`strconv`、`strings`、`time`、`encoding/json`、`itbase.dev/itb`，以及接口文件对 `itbase.app/{appCode}/domain` 的引用
- `go` 语句
- `select`、`defer` 以外的裸 `go` 调用；`defer` 允许
- `init` 函数
- 类型参数、泛型实例化
- `unsafe`、`reflect`、`import _`
- cgo、`//go:embed`、构建标签

`defer` 允许，用来在领域函数里表达释放之外的本地清理；由于没有拿到文件和连接，清理对象只有内存值。

标准库子集与解释器安全边界见 [解释器运行时](06-解释器运行时.md)。宿主不把 `*gdb.DB`、SQL 字符串、DDL、标准库 `os` / `net` 交给解释器。

## 5. 与数据管线的关系

自定义接口返回的记录形状与 [数据读写第 4 节](04-数据读写.md) 一致时，直接把 `itb.Record` 放进 `Response.Body`。需要别的形状时，在接口包里组装 `map`。

工作流以后要执行业务动作时，调用已发布的领域函数，不另写一套脚本语言，也不在工作流里打开第二个不受本节限制的解释器。

## 6. 本模块完成标准

- 不重新编译平台，能够保存草稿、检查、发布一份含领域包和接口包的修订。
- 发布失败时，原已发布修订继续服务。
- 源码 import `os` 或写出 `go` 语句时，`:check` 失败，运行池不变。
- 两个并发的首次 `PUT` 只会留下一行 `draft`。`baseEditVersion` 过期时返回 409。
- `/orders/{id}` 与 `/orders/{no}` 在 `:check` 失败；`/orders/new` 在运行时命中字面模板。
