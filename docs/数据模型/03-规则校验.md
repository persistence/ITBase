# 规则校验

职责：用 CEL 文本保存跨字段、跨记录的业务规则；服务端用 cel-go 执行，前端执行同一段文本。写入路径上的校验顺序也由本模块规定。

不负责：必填、类型、长度、唯一（由 [元数据目录](01-元数据目录.md) 与数据库约束负责）；把校验嵌进事务并落库（由 [数据读写](04-数据读写.md) 调用本模块）。

依赖：元数据目录里 `active` 且允许进入 CEL 的字段，以及 `active` 关联的导航编码。

规则的增删改只写目录，不产生 DDL，保存成功即生效。

## 1. dm_rule

```sql
CREATE TABLE dm_rule (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '规则主键',
  entity_id   BIGINT UNSIGNED NOT NULL COMMENT '所属实体',
  code        VARCHAR(40)     NOT NULL COMMENT '规则编码，创建后不改',
  title       VARCHAR(80)     NOT NULL COMMENT '显示名',
  scope       VARCHAR(16)     NOT NULL COMMENT 'local 或 server。server 不下发前端',
  expr        TEXT            NOT NULL COMMENT 'CEL 表达式。保存时必须编译通过，结果类型为 bool',
  message     VARCHAR(200)    NOT NULL COMMENT '校验失败时返回的文案',
  fields_json JSON            NULL COMMENT '表达式引用的字段编码。保存时从编译结果抽出',
  reads_json  JSON            NULL COMMENT 'server 规则声明要读取的导航编码。local 为空',
  enabled     TINYINT(1)      NOT NULL DEFAULT 1 COMMENT '1 启用。停用字段前仍会检查启用中的引用',
  sort_no     INT             NOT NULL DEFAULT 0 COMMENT '同一实体上的执行顺序',
  created_at  DATETIME(3)     NOT NULL COMMENT '创建时间，UTC',
  updated_at  DATETIME(3)     NOT NULL COMMENT '更新时间，UTC',
  PRIMARY KEY (id),
  UNIQUE KEY uk_dm_rule (entity_id, code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT 'CEL 规则。只写目录，不产生 DDL';
```

`scope`：`local` 或 `server`。`fields_json` 是表达式里出现的字段编码，保存时从编译结果抽出。`reads_json` 仅 `server` 使用，内容是导航编码数组。停用或清除字段、导航前，目录模块用这两列拒绝仍被启用规则引用的对象。`expr` 必须编译通过，且求值结果类型为 `bool`。

```text
POST   /apps/{appCode}/entities/{entityCode}/rules
PATCH  /apps/{appCode}/entities/{entityCode}/rules/{ruleCode}
DELETE /apps/{appCode}/entities/{entityCode}/rules/{ruleCode}

GET    /apps/{appCode}/entities/{entityCode}/validate-spec
```

## 2. 规则看什么

保存时把表达式放进受控环境编译。环境版本号为 `cel-profile/v1`。

`local` 规则的变量只有：

```text
record.<fieldCode>
old.<fieldCode>
```

`record` 是类型转换和标准化之后、写入之前的整行。`PATCH` 先把请求里出现的键合并进库中的当前行，再交给规则；未出现的键保持库里的值，显式 `null` 才是清空。`old` 在创建时各字段为 `null`，在更新时是合并前的库中整行。两边都只有目录里标成可进入 CEL 的字段。`json`、`file`、`ref` 不在环境里。`bigint` 与 `decimal` 一样是十进制字符串。

`server` 规则在上述变量之外增加：

```text
link.<navCode>
```

`reads_json` 里声明的导航才会被放进环境。多的一侧是列表，一的一侧是单个 map 或 `null`。map 的键是目标实体里允许进入 CEL 的字段，外加 `id`。未声明的导航不能出现在表达式里。

第一期函数白名单：

- 比较与逻辑：`== != < <= > >= && || !`
- 字符串与集合：`contains`、`startsWith`、`endsWith`、`matches`、`size`、`in`。`matches` 的正则是 RE2，与 cel-go 一致。前端不得用 JavaScript `RegExp` 执行这一函数，要使用 RE2 实现
- 十进制：`decCmp(a, b)` 返回 int，`decAdd`、`decSub`、`decMul` 的参数和返回值都是十进制字符串

不提供 `now`、自定义 IO、反射数据库。时间比较使用标准化后的 UTC 字符串。CEL 本身没有用户可写的循环；`.exists` 一类宏只允许作用在本次请求已经装入的 `link` 列表上。

`local` 规则的表达式若引用 `link`、`old` 以外的未知标识，或调用白名单外的函数，保存接口返回 400。`server` 规则不允许下发给前端。

数据事务使用 `REPEATABLE READ`。`server` 规则里的 `SELECT` 不加锁，只能看见本事务已经写入的行和事务开始时的快照。两个并发事务可以同时通过「不存在另一行」这类表达式。这类不变量用唯一索引，或在领域函数里做 `SELECT … FOR UPDATE`。

规则在每一行插入或更新之前执行，提交前不再把整张写入图复查一遍。父行的规则看不到同一次请求里稍后才写入的子行。订单合计等于订单行之和，要在领域函数里于子行写完后自己读出来判断。

删除不进入 CEL。不能删除已确认订单这类约束写在领域函数里，并避免把通用 `DELETE` 暴露给会绕过该函数的调用方。

跨多行写入、需要循环聚合或要返回自定义形状的响应时，不写 CEL，改写 [源码与发布](05-源码与发布.md) 里的领域函数。领域函数里的每一次 `Create` / `Update` 仍会跑该实体的 CEL。

## 3. 前后端怎么跑同一段 CEL

服务端使用 cel-go：按 `cel-profile/v1` 建环境，编译结果按表达式文本的哈希缓存，求值结果必须是 `bool`。`false` 表示校验失败，把规则的 `code` 和 `message` 返回给调用方。

前端不嵌入 cel-go。前端使用一份对齐 CEL 规范的 JavaScript 实现，只开启同一份函数白名单，并实现同样的 `decCmp`、`decAdd`、`decSub`、`decMul`。

两边在求值前做同一种标准化：

- 字符串去掉首尾空白；空字符串视为 `null`
- `decimal` 去掉多余的 0 和指数形式，保留标度内的十进制字符串
- `datetime` 转成 UTC、毫秒三位的 RFC3339
- `date` 保持 `YYYY-MM-DD`
- `bool` 只接受 JSON 布尔

`GET …/validate-spec` 返回前端执行所需要的全部信息：`profile`、字段的 CEL 类型、标准化规则名、全部 `enabled` 且 `scope = local` 的表达式与文案。不返回 `server` 规则。

仓库里放一组 JSON 夹具：表达式、标准化前输入、期望布尔值。Go 与 JavaScript 各跑一遍。白名单或标准化有改动时，先改夹具再改两端实现。

服务端在写入路径上仍会执行全部 `local` 规则。前端校验只减少往返，不作为安全边界。

## 4. 一条写入里的校验顺序

对图中的每一行：

1. 拒绝未知字段、未知导航、类型不匹配的 JSON。
2. 按第 3 节标准化。
3. 检查必填、字符串长度、小数精度、选项编码是否启用、外键目标是否存在。
4. 执行该实体的 `local` 规则。
5. 装入 `reads_json` 声明的关联：请求里已经带上的用请求数据，没带上的在当前事务里 `SELECT`。
6. 执行 `server` 规则。
7. `INSERT` 或 `UPDATE`。

任一步失败则整个数据事务回滚。响应使用 422，正文列出 `entityCode`、行临时键、`ruleCode` 或约束名、`message`。

数据读写模块在每插入或更新一行之前跑完以上顺序。`server` 规则能看见本事务里已经写入的行。

## 5. 本模块完成标准

- `local` 规则出现在 `validate-spec` 里，Go 与 JavaScript 夹具全部通过，`matches` 的夹具覆盖 RE2 与 JavaScript `RegExp` 语义不同的模式。
- `server` 规则能读取声明过的关联。
- 保存时拒绝前端跑不了的 `local` 写法，拒绝未声明导航的 `server` 写法。
- `PATCH` 只带一个字段时，规则仍能读到该行其余已落库的字段。
