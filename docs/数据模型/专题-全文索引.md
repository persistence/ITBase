# 全文索引

专题，不是独立实现模块。为 `string`、`text` 提供可选的 MySQL `FULLTEXT` 索引，包括单列和多列联合；列表查询按目录里的某一条全文索引检索。登记在元数据目录，DDL 走结构同步，`search` 在数据读写的列表计划里执行。代码上是这三处调用的一个小库。阅读时放在数据读写旁边。

不负责：B 树索引与唯一约束（见 [元数据目录](01-元数据目录.md)）；DDL 任务状态机（见 [结构同步](02-结构同步.md)）；`contains` 的 `LIKE` 匹配（见 [数据读写](04-数据读写.md)）。外部搜索引擎不在本专题。

依赖：元数据目录、结构同步、数据读写。查询只使用 `active` 的全文索引。

## 1. 登记在索引上

一条全文索引固定一组列，以及这组列的顺序。`MATCH(列…) AGAINST(…)` 必须与某一条 `FULLTEXT` 索引的列集合、列顺序一致，才能用上该索引。

因此「可搜索」不是字段属性。同一字段既要单独搜，又要和其它字段一起搜，就登记多条全文索引。例如 `title` 一条、`body` 一条、`(title, body)` 再一条。

`dm_index.index_kind` 取值：

| index_kind | unique_key | 物理名 | 软删除令牌 |
|---|---|---|---|
| `btree` | 0 或 1 | `ix_{entityId}_{indexId}` | 唯一索引在列尾追加 `deleted_token` |
| `fulltext` | 固定 0 | `ft_{entityId}_{indexId}` | 不追加 |

`index_kind` 创建后不改。全文索引不能声明为唯一索引。

## 2. 允许的列

全文索引的列只能是该实体上 `active` 的 `string` 或 `text`。列数 1–5，顺序以 `dm_index_column.seq` 为准。

`option`、`json`、`file`、数值、日期、`ref` 以及 `deleted_token` 不能进入全文索引。`text` 也不能进入 B 树索引。`string` 超过 B 树键长时仍可进入全文索引，键长限制见 [元数据目录 5.5](01-元数据目录.md)。

同一实体上，列集合相同的全文索引只保留一条。比较时忽略顺序以外的差异：集合相同即拒绝，即使请求里的顺序不同。已有索引的 `status` 为 `pending`、`active` 或 `failed` 都算占用。

每个实体最多 3 条上述状态的全文索引。

## 3. 创建与删除

结构 API 仍是：

```text
POST   /apps/{appCode}/entities/{entityCode}/indexes
DELETE /apps/{appCode}/entities/{entityCode}/indexes/{indexCode}
```

创建请求：

```json
{
  "code": "keyword",
  "kind": "fulltext",
  "fields": ["title", "body"]
}
```

`kind` 省略时为 `btree`。`kind = fulltext` 时 `fields` 为 1–5 个字段编码，顺序即索引列序。

目录与任务的写法和 B 树索引相同：短事务里插入 `dm_index`（`status = pending`，`unique_key = 0`，`index_kind = fulltext`）、`dm_index_column` 和一条 `add_index` 任务，提交后在事务外执行 DDL。删除插入 `drop_index` 任务。

字段清除（`purge`）前，该字段不能仍出现在任何 `dm_index_column` 中。先删除索引，再清除字段。

## 4. DDL

`forward_ddl` / `reverse_ddl` 由目录中的物理名和列序生成，例如：

```sql
ALTER TABLE app__ticket
  ADD FULLTEXT INDEX ft_12_34 (title, body) WITH PARSER ngram;

ALTER TABLE app__ticket DROP INDEX ft_12_34;
```

平台统一使用 `ngram` 解析器，不在 `dm_index` 上另存解析器名字。默认空格分词会把一段中文收成一个词，故不使用 MySQL 默认全文解析器。

结构核对除索引名和列序外，还要比对 `information_schema.STATISTICS.INDEX_TYPE = 'FULLTEXT'`。

大表上的 `ADD FULLTEXT INDEX` 会重建该索引，并持有元数据锁。全文索引任务提交目录后立即返回 202，执行超时要比普通 `ADD INDEX` 放宽。见 [结构同步](02-结构同步.md)。

## 5. 服务器参数

MySQL 8 实例按下面的值配置。`ngram_token_size` 是全局参数，改动后需要重启，不能按索引分别设置。

| 参数 | 值 | 作用 |
|---|---|---|
| `ngram_token_size` | `2` | 按二字切分，中文检索以词为单位 |
| `innodb_ft_enable_stopword` | `OFF` | 关闭默认英文停用词，避免常用英文词被静默丢掉 |

`ngram_token_size = 2` 时，短于 2 个字的词元不会被索引。服务端按空白切开 `q` 之后，任一词的码点长度小于 2，整段请求返回 400，不执行 `MATCH`。`合同 A` 因此返回 400，而不是悄悄丢掉 `A`。整段去掉空白后长度小于 2 时同样返回 400。

## 6. 列表查询

`:query` 在 `filter` 之外接受可选的 `search`。它只作用于当前实体，不能写导航路径。`search` 与 `filter`、软删除条件、读权限条件同时成立。

```json
{
  "search": { "index": "keyword", "q": "合同 付款" },
  "filter": { "field": "status", "op": "eq", "value": "open" }
}
```

| 字段 | 约束 |
|---|---|
| `search` | 可空 |
| `search.index` | 当前实体上 `active` 的全文索引编码 |
| `search.q` | 去掉首尾空白后长度 1–80 |

未知索引、索引不是全文索引、索引未 `active`，返回 400。`q` 含 `"` 或 `*` 时返回 400。

服务端按空白切词。每个词用双引号包起并加上 `+`，使这些词必须同时出现。上例改写为：

```text
+"合同" +"付款"
```

词内的 `-` 留在引号中，布尔模式不会把它当成排除运算符。改写结果只通过绑定参数进入 `AGAINST`，不拼进 SQL 文本。

```sql
SELECT ...
FROM app__ticket
WHERE MATCH(title, body) AGAINST (? IN BOOLEAN MODE)
  AND deleted_token = 0
  AND status = ?
ORDER BY MATCH(title, body) AGAINST (? IN BOOLEAN MODE) DESC, id DESC
LIMIT ?
```

`MATCH` 的列按 `dm_index_column.seq` 输出。`ORDER BY` 中的 `AGAINST` 绑定同一参数。

未指定 `sort` 时按相关度降序，再用 `id` 降序。指定了 `sort` 时，全文条件只参与 `WHERE`，排序仍按 [数据读写 4.2](04-数据读写.md) 的字段排序。响应不返回相关度分数。

`COUNT(*)` 使用同一组 `WHERE`，包括 `MATCH`，不加 `ORDER BY`。

`string` 上的 `contains`、`startsWith`、`endsWith` 仍走 `LIKE`。`text` 不能出现在 `filter` 的 `field` 上；检索 `text` 只能通过覆盖它的全文索引。

解释器 `Query` 使用同一 `search` 对象。

## 7. 软删除与可见性

已软删除的行仍留在全文索引里，直到物理删除。列表靠 `deleted_token = 0` 排除它们。实体关闭软删除时，查询不加该条件。

`MATCH` 只看见已提交的数据。同一事务内刚刚插入或更新的行，本事务里的全文查询看不见。数据 API 的写入事务不在提交前做 `:query`。解释器若在 `Tx` 里写入后立刻 `Query`，全文条件可能漏掉本次未提交的改动。

## 8. 和变更历史的边界

库内全文检索由数据 API 直接查询业务表，不读 `dm_record_change`，也不注册消费者。

[变更历史](05-变更历史.md) 里的消费者名 `search_index` 留给以后的外部搜索引擎。外部引擎若要知道哪些列参与检索，以目录里 `active` 的全文索引为准。

## 9. 本专题完成标准

- 能为 `string`、`text` 创建单列全文索引，以及 2–5 列的联合全文索引；第六列、第四条全文索引、重复列集合、非文本列均被拒绝。
- DDL 使用 `FULLTEXT INDEX … WITH PARSER ngram`；删除索引后目录与 `information_schema` 一致。
- `:query` 的 `search` 与 `filter`、`deleted_token = 0` 同时生效；多词按必须同时出现处理。含单字词元的 `q` 返回 400。
- 未指定 `sort` 时相关度高的行排在前面；指定 `sort` 时排序列不被相关度替换。
- `contains` 仍生成 `LIKE`，不生成 `MATCH`。
