# 会话

职责：在登录方式已经解析出一名 `active` 用户之后，签发、续期和注销会话。管理端和各应用 client 携带同一份会话。停用和离职时，作废这个人尚未注销的会话。

不负责：口令是否正确、外部身份如何解析（见 [登录方式](05-登录方式.md)）；用户主数据（见 [用户](01-用户.md)）。本模块不签发给应用代码使用的第二套令牌。

依赖：用户 id 和状态来自 [用户](01-用户.md)。停用、离职的事务调用本模块的作废。

接口前缀 `/api/v1/org`。`auth:login` 不要求已登录。其余接口要求当前会话有效。

## 1. org_session

```sql
CREATE TABLE org_session (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '会话主键',
  user_id       BIGINT UNSIGNED NOT NULL COMMENT 'org_user.id',
  token_hash    CHAR(64)        NOT NULL COMMENT '会话令牌的 SHA-256，十六进制。明文只放进 cookie',
  created_at    DATETIME(3)     NOT NULL COMMENT '签发时间，UTC',
  expires_at    DATETIME(3)     NOT NULL COMMENT '绝对过期时间，UTC。续期不能越过它',
  last_seen_at  DATETIME(3)     NOT NULL COMMENT '最近一次通过校验的时间，UTC',
  revoked_at    DATETIME(3)     NULL COMMENT '注销时间，UTC。未注销为空',
  PRIMARY KEY (id),
  UNIQUE KEY uk_org_session_token (token_hash),
  KEY idx_org_session_user (user_id, revoked_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '会话。不进目录';
```

令牌是 32 字节随机值，cookie 里放它的十六进制。库里只存 SHA-256。比较时先哈希再查表，不把明文写进日志和响应正文。

绝对寿命 12 小时，从 `created_at` 起算。空闲超过 2 小时视为失效：已认证请求距 `last_seen_at` 不超过 2 小时时，把 `last_seen_at` 更新为当前 UTC 时间；超过则把 `revoked_at` 写成当前时间并返回 401。更新 `last_seen_at` 使用应用传入的 UTC 时间，不用 `NOW()`。

一个人可以同时有多条未注销会话。

## 2. 携带方式

浏览器通过 cookie 携带：

| 属性 | 值 |
|---|---|
| 名称 | `itbase_session` |
| HttpOnly | 是 |
| Secure | 是 |
| SameSite | `Lax` |
| Path | `/` |
| Max-Age | 与绝对寿命相同，12 小时 |

壳和按 `appCode` 加载的 client 与内核同源，因此共用这枚 cookie。第一期不把令牌放进 JSON，也不提供 `Authorization` 头。

注销和失效时同时写 `revoked_at`，并在响应里清除 cookie。

## 3. 作废

停用和离职在修改用户状态的同一事务里调用作废：把该 `user_id` 下 `revoked_at` 为空的行全部写成当前 UTC 时间。启用用户不会恢复已作废的会话，本人需要重新登录。

`POST /auth:logout` 只作废当前这一条。

## 4. 接口

| 方法与路径 | 作用 |
|---|---|
| `POST /api/v1/org/auth:login` | 按 [登录方式](05-登录方式.md) 的第一期口令管道登录。成功时写 cookie，正文为用户 id、登录名和姓名 |
| `POST /api/v1/org/auth:logout` | 作废当前会话并清除 cookie |
| `GET /api/v1/org/auth:session` | 读取当前会话对应的用户 id、登录名、姓名和状态 |

`auth:session` 在会话缺失、哈希对不上、已注销、已过绝对寿命或空闲超时、以及用户状态不是 `active` 时，都返回 401，并清除 cookie。用户行在会话签发后被停用或离职时，同样 401。

## 5. 错误

| HTTP | 何时 |
|---|---|
| 401 | 登录失败，口径与 [用户](01-用户.md) 的 `auth:verify` 相同；会话无效 |
| 400 | 登录请求缺字段，或字段类型不对 |

登录失败不写会话行。

## 6. 本模块完成标准

- 登录名和口令正确、状态为 `active` 时，响应带上 `itbase_session`，随后 `auth:session` 返回该用户。
- 口令错误、用户不存在、停用、离职，登录都返回 401，且不写 cookie。
- 停用或离职的事务提交后，该用户此前的会话再访问返回 401。
- `auth:logout` 之后，同一 cookie 再访问返回 401。另一条未注销会话仍然有效。
- 空闲超过 2 小时，或签发超过 12 小时，访问返回 401。
