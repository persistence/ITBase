# 部门与职位

职责：维护部门树、职位名录，以及人在部门中的任职。部门负责人不在部门行上保存，而是 [组织角色](03-组织角色.md) 里 `dept_leader` 的绑定。

不负责：用户账号（见 [用户](01-用户.md)）；角色上的人有什么数据权限；编制、职级和汇报线。

依赖：用户必须已经存在，任职才能引用他。权限模块通过主体事实读取本模块维护的闭包，不直接改这些表。

接口前缀 `/api/v1/org`。写操作要求 `platform_admin`。已登录用户可以查询部门和职位，以及自己的任职。

## 1. 部门

```sql
CREATE TABLE org_department (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '部门主键',
  code          VARCHAR(40)     NOT NULL COMMENT '部门编码。创建后不改',
  title         VARCHAR(80)     NOT NULL COMMENT '部门名称。目录实体 department 的标题字段',
  parent_id     BIGINT UNSIGNED NULL COMMENT '上级部门。根部门为空',
  sort_order    INT             NOT NULL DEFAULT 0 COMMENT '同一上级下的显示顺序，小的在前',
  status        VARCHAR(16)     NOT NULL COMMENT 'active、disabled',
  row_version   BIGINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '乐观锁',
  created_at    DATETIME(3)     NOT NULL COMMENT '创建时间，UTC',
  created_by    BIGINT UNSIGNED NOT NULL COMMENT '创建人用户 id',
  updated_at    DATETIME(3)     NOT NULL COMMENT '最后修改时间，UTC',
  updated_by    BIGINT UNSIGNED NOT NULL COMMENT '最后修改人用户 id',
  root_key      TINYINT         AS (CASE WHEN parent_id IS NULL THEN 1 ELSE NULL END) STORED COMMENT '根部门标记。唯一索引保证只有一个根',
  PRIMARY KEY (id),
  UNIQUE KEY uk_org_dept_code (code),
  UNIQUE KEY uk_org_dept_root (root_key),
  KEY idx_org_dept_parent (parent_id, sort_order, id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '部门';
```

编码符合 `^[a-z][a-z0-9_]{0,39}$`。根部门的编码是 `root`，由初始化写入。

新建部门时指定一个 `active` 的上级。`parent_id` 不能改成空。移动使用单独的接口，在一个事务里完成：

1. 锁住被移动的部门行。
2. 新上级必须是 `active` 的部门，且不是自己，也不是自己的下级。判断下级时读闭包表。
3. 更新 `parent_id`。
4. 按下一节重写闭包。

停用部门前，它不能有 `active` 的直接下级，也不能有未结束的任职。根部门拒绝移动和停用。不提供删除部门的接口。已经停用的部门拒绝作为新上级、新任职的部门，也拒绝作为新建业务引用的目标。

目录实体 `department` 对外可见的字段是 `code`、`title`、`status`。`parent_id` 留在本模块，不登记成自关联。

## 2. 闭包

```sql
CREATE TABLE org_dept_closure (
  ancestor_id   BIGINT UNSIGNED NOT NULL COMMENT '祖先部门，含自身',
  descendant_id BIGINT UNSIGNED NOT NULL COMMENT '下级部门，含自身',
  depth         INT UNSIGNED    NOT NULL COMMENT '距离。自身为 0，直接下级为 1',
  PRIMARY KEY (ancestor_id, descendant_id),
  KEY idx_org_dept_closure_desc (descendant_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '部门闭包。与部门父子关系在同一事务维护';
```

每个部门都有一行自己到自己的记录，`depth = 0`。新建部门时，复制上级的全部祖先，深度加 1，再写入自身。

移动部门时，先算出以该部门为祖先的全部下级（含自身），再删除「祖先在这棵子树之外、下级在这棵子树之内」的闭包行，然后按新上级的祖先重新插入。子树内部的相对深度不变。

查询「部门 D 及其全部下级」是 `ancestor_id = D`。主体事实用这个结果展开人所在部门，不在每次业务列表里递归部门表。

## 3. 职位

```sql
CREATE TABLE org_position (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '职位主键',
  code          VARCHAR(40)     NOT NULL COMMENT '职位编码。创建后不改',
  title         VARCHAR(80)     NOT NULL COMMENT '职位名称',
  status        VARCHAR(16)     NOT NULL COMMENT 'active、disabled',
  row_version   BIGINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '乐观锁',
  created_at    DATETIME(3)     NOT NULL COMMENT '创建时间，UTC',
  created_by    BIGINT UNSIGNED NOT NULL COMMENT '创建人用户 id',
  updated_at    DATETIME(3)     NOT NULL COMMENT '最后修改时间，UTC',
  updated_by    BIGINT UNSIGNED NOT NULL COMMENT '最后修改人用户 id',
  PRIMARY KEY (id),
  UNIQUE KEY uk_org_position_code (code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '职位名录。全组织共用，不挂在部门下';
```

职位描述职务名称，例如「销售经理」。它不表示权限，也不表示部门里的一个编制名额。停用后不能用于新任职；已经引用它的未结束任职保持原样，直到任职结束。不提供删除。

## 4. 任职

```sql
CREATE TABLE org_membership (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '任职主键',
  user_id       BIGINT UNSIGNED NOT NULL COMMENT 'org_user.id',
  dept_id       BIGINT UNSIGNED NOT NULL COMMENT 'org_department.id',
  position_id   BIGINT UNSIGNED NULL COMMENT 'org_position.id。未指定职位为空',
  is_primary    TINYINT(1)      NOT NULL DEFAULT 0 COMMENT '1 表示主部门',
  open_token    BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '未结束为 0。结束后写成该行 id',
  started_at    DATETIME(3)     NOT NULL COMMENT '开始时间，UTC',
  ended_at      DATETIME(3)     NULL COMMENT '结束时间，UTC。未结束为空',
  row_version   BIGINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '乐观锁',
  created_at    DATETIME(3)     NOT NULL COMMENT '创建时间，UTC',
  created_by    BIGINT UNSIGNED NOT NULL COMMENT '创建人用户 id',
  updated_at    DATETIME(3)     NOT NULL COMMENT '最后修改时间，UTC',
  updated_by    BIGINT UNSIGNED NOT NULL COMMENT '最后修改人用户 id',
  primary_user  BIGINT UNSIGNED AS (CASE WHEN is_primary = 1 AND open_token = 0 THEN user_id ELSE NULL END) STORED COMMENT '当前主部门的用户。唯一索引保证每人最多一个',
  PRIMARY KEY (id),
  UNIQUE KEY uk_org_membership_open (user_id, dept_id, open_token),
  UNIQUE KEY uk_org_membership_primary (primary_user),
  KEY idx_org_membership_dept (dept_id, open_token)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '任职';
```

一条未结束任职表示这个人当前在这个部门。同一人在同一部门只能有一条未结束任职。职位可以空着，以后再补。

主部门是这些任职中的一条。设置主部门时锁住该用户全部未结束任职，把原来的主部门改成 `0`，再把目标改成 `1`。结束主部门任职时把 `is_primary` 改回 `0`，再把 `open_token` 写成该行 id。结束之后这个人可以暂时没有主部门。

新建任职要求用户状态为 `active`，部门状态为 `active`。职位若填写，状态必须为 `active`。用户离职时由用户模块在同一事务里结束他的全部未结束任职。

结束过的行留在表里，按用户或部门可以查到开始和结束时间。第一期不按某个历史日期重放当时的部门。

## 5. 接口

| 方法与路径 | 作用 |
|---|---|
| `POST /api/v1/org/departments` | 在指定上级下创建部门，并写入闭包 |
| `PATCH /api/v1/org/departments/{id}` | 修改名称和 `sortOrder`。编码、上级不在请求体里 |
| `GET /api/v1/org/departments/{id}` | 读取一个部门 |
| `POST /api/v1/org/departments:query` | 按上级、状态、名称查询。`parentId` 为空时返回根 |
| `POST /api/v1/org/departments/{id}:move` | 移动到新上级 |
| `POST /api/v1/org/departments/{id}:disable` | 停用 |
| `POST /api/v1/org/departments/{id}:enable` | 启用。上级必须是 `active` |
| `POST /api/v1/org/positions` | 创建职位 |
| `PATCH /api/v1/org/positions/{id}` | 修改职位名称 |
| `POST /api/v1/org/positions:query` | 按编码、名称、状态查询 |
| `POST /api/v1/org/positions/{id}:disable` | 停用职位 |
| `POST /api/v1/org/positions/{id}:enable` | 启用职位 |
| `POST /api/v1/org/memberships` | 新建任职。`primary` 为真时同时设成主部门 |
| `PATCH /api/v1/org/memberships/{id}` | 修改未结束任职的职位 |
| `POST /api/v1/org/memberships/{id}:end` | 结束任职 |
| `POST /api/v1/org/memberships/{id}:set-primary` | 把这条未结束任职设为主部门 |
| `POST /api/v1/org/memberships:query` | 按用户、部门、是否未结束查询 |

移动、停用、设置主部门都带部门或任职的 `rowVersion`。

## 6. 错误

| HTTP | 何时 |
|---|---|
| 400 | 编码不合法；任职的用户、部门、职位缺失 |
| 401 | 未登录 |
| 403 | 非 `platform_admin` 执行写操作 |
| 404 | 部门、职位、用户或任职不存在 |
| 409 | 编码冲突；`rowVersion` 不匹配；移动形成环；停用时仍有下级或未结束任职；对根部门移动或停用；目标不是 `active`；该人在该部门已有未结束任职 |

## 7. 本模块完成标准

- 初始化之后只有一个 `parent_id` 为空的部门，闭包含自身。
- 创建三级部门后，根的闭包能列出这三级。把中间部门移到根下之后，闭包深度跟着变，子部门仍挂在中间部门下。
- 把部门移到它自己的下级时，部门和闭包都保持移动前的样子。
- 同一人两条未结束任职里，后设置的主部门生效，原来的主部门标志被清掉。
- 停用的职位不能出现在新建任职上；停用前已经写下的任职仍能读出职位名称。
