# 用户

职责：维护组织里的人。一个人有稳定的数字 id、登录名、姓名和状态。本模块校验口令，并声明登录成功后的主体就是 `org_user.id`。

不负责：会话的签发、续期和注销（见 [会话](04-会话.md)）；登录方式的编排（见 [登录方式](05-登录方式.md)）；菜单与数据范围（见 [组织角色](03-组织角色.md) 交给权限模块的事实）；部门树和任职（见 [部门与职位](02-部门与职位.md)）。

依赖：无。部门和角色都引用本模块的用户 id。

接口前缀 `/api/v1/org`。除 `auth:verify` 外都要求已登录。写用户、重置他人口令、绑定外部身份要求调用者持有 `platform_admin`。已登录用户可以读取自己的资料并修改自己的口令。

## 1. org_user

```sql
CREATE TABLE org_user (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '用户主键。等于 created_by、updated_by、actor_id',
  login_name    VARCHAR(64)     NOT NULL COMMENT '登录名。创建后不改',
  employee_no   VARCHAR(32)     NULL COMMENT '工号。未分配为空',
  display_name  VARCHAR(80)     NOT NULL COMMENT '姓名。目录实体 user 的标题字段',
  email         VARCHAR(254)    NULL COMMENT '邮箱。未填为空',
  mobile        VARCHAR(20)     NULL COMMENT '手机号。未填为空',
  status        VARCHAR(16)     NOT NULL COMMENT 'active、disabled、left',
  row_version   BIGINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '乐观锁。插入为 1',
  created_at    DATETIME(3)     NOT NULL COMMENT '创建时间，UTC',
  created_by    BIGINT UNSIGNED NOT NULL COMMENT '创建人用户 id。初始化的第一名用户写 0',
  updated_at    DATETIME(3)     NOT NULL COMMENT '最后修改时间，UTC',
  updated_by    BIGINT UNSIGNED NOT NULL COMMENT '最后修改人用户 id',
  left_at       DATETIME(3)     NULL COMMENT '离职时间，UTC。未离职为空',
  PRIMARY KEY (id),
  UNIQUE KEY uk_org_user_login (login_name),
  UNIQUE KEY uk_org_user_employee (employee_no),
  UNIQUE KEY uk_org_user_email (email),
  UNIQUE KEY uk_org_user_mobile (mobile)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '用户';
```

登录名在去掉首尾空白后保存。允许的字符是字母、数字、`.`、`_`、`-`，长度 1–64，不能以 `.`、`_`、`-` 开头。比较按表的排序规则，不区分大小写。

工号、邮箱、手机号去掉首尾空白。空字符串存成 `NULL`。三者各自唯一；未填写的用户互不冲突。

`status` 只允许这些变化：`active → disabled`、`disabled → active`、`active → left`、`disabled → left`。进入 `left` 时写下 `left_at`。第一期没有从 `left` 恢复的接口。

离职与停用的差别：停用只把状态改为 `disabled`，任职和角色绑定保持原样，启用后仍然有效。离职在同一事务里把状态改为 `left`，并结束这个人全部未结束的任职和角色绑定。两种状态都在同一事务里作废该用户全部未注销会话，规则见 [会话](04-会话.md)。两种状态下，主体事实里的部门集合和角色集合都为空。姓名接口照常返回，供历史单据显示创建人。

不提供物理删除。

目录实体 `user` 对外可见的字段是 `login_name`、`employee_no`、`display_name`、`email`、`mobile`、`status`。口令和外部身份不进目录。

## 2. org_credential

```sql
CREATE TABLE org_credential (
  user_id        BIGINT UNSIGNED NOT NULL COMMENT 'org_user.id',
  password_hash  VARCHAR(255)    NOT NULL COMMENT '口令哈希',
  algo           VARCHAR(32)     NOT NULL COMMENT '哈希算法标识',
  updated_at     DATETIME(3)     NOT NULL COMMENT '最近一次设置口令的时间，UTC',
  updated_by     BIGINT UNSIGNED NOT NULL COMMENT '设置口令的用户 id。本人修改时等于 user_id',
  PRIMARY KEY (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '口令。任何查询接口都不返回本表';
```

创建用户时必须同时写入一行凭据。口令只在设置时出现在请求体里，响应、日志和变更记录里都不留下明文或哈希。

第一期算法固定为一种口令哈希，具体算法在实现时选定并写入 `algo`。校验时按该行的 `algo` 计算，不根据配置猜测。

## 3. org_external_identity

```sql
CREATE TABLE org_external_identity (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '绑定主键',
  user_id      BIGINT UNSIGNED NOT NULL COMMENT 'org_user.id',
  provider     VARCHAR(32)     NOT NULL COMMENT '身份源编码，如 wecom、dingtalk、ldap',
  external_id  VARCHAR(128)    NOT NULL COMMENT '身份源中的主体 id',
  created_at   DATETIME(3)     NOT NULL COMMENT '绑定时间，UTC',
  created_by   BIGINT UNSIGNED NOT NULL COMMENT '操作者用户 id',
  PRIMARY KEY (id),
  UNIQUE KEY uk_org_ext_provider (provider, external_id),
  KEY idx_org_ext_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '外部身份。第一期只提供手工绑定';
```

同一身份源里的一个外部 id 只能绑到一个用户。一个用户可以有多条绑定。第一期不从身份源拉取组织，也不用外部身份登录。以后哪种身份源可以登录，见 [登录方式](05-登录方式.md)。

## 4. 接口

| 方法与路径 | 作用 |
|---|---|
| `POST /api/v1/org/users` | 创建用户和口令 |
| `PATCH /api/v1/org/users/{id}` | 修改姓名、工号、邮箱、手机。带 `rowVersion`。登录名不在请求体里 |
| `GET /api/v1/org/users/{id}` | 读取一名用户。不含口令 |
| `POST /api/v1/org/users:query` | 按登录名、姓名、工号、状态筛选 |
| `POST /api/v1/org/users/{id}:disable` | `active → disabled` |
| `POST /api/v1/org/users/{id}:enable` | `disabled → active` |
| `POST /api/v1/org/users/{id}:leave` | 离职，并结束任职与角色绑定 |
| `PUT /api/v1/org/users/{id}/credential` | 设置新口令 |
| `POST /api/v1/org/auth:verify` | 校验登录名和口令 |
| `POST /api/v1/org/users/{id}/external-identities` | 增加外部身份 |
| `DELETE /api/v1/org/external-identities/{id}` | 解除外部身份 |

`auth:verify` 在登录名存在、口令匹配且状态为 `active` 时返回用户 id、登录名和姓名。登录名不存在、口令不匹配、状态不是 `active`，都返回同一个 401，响应正文不说明是哪一种。

用户查询按 `id` 降序分页。`page` 从 1 开始，`size` 最大 100。`OFFSET` 超过 10000 时返回 400。

## 5. 错误

| HTTP | 何时 |
|---|---|
| 400 | 登录名、工号、邮箱、手机号不符合格式；JSON 里的 id 或 `rowVersion` 用了数字 |
| 401 | `auth:verify` 失败；其他接口未登录 |
| 403 | 非 `platform_admin` 执行管理操作；修改他人资料 |
| 404 | 用户不存在 |
| 409 | 登录名、工号、邮箱、手机号或外部身份冲突；`rowVersion` 不匹配；当前状态不允许该操作 |

## 6. 本模块完成标准

- 创建用户后可以用登录名通过 `auth:verify`。响应和日志中没有口令哈希。
- 停用后 `auth:verify` 返回 401；再启用后恢复。
- 离职后姓名仍能由 `GET` 读到，未结束的任职和角色绑定都带上结束时间。
- 两个请求用同一个 `rowVersion` 修改同一用户时，只有一个成功。
- 把同一个外部 id 绑给第二个用户时返回 409。
