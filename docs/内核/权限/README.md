# 权限

产品名称用「权限」。它把 [组织角色](../用户与组织/03-组织角色.md) 给出的主体事实编译成数据范围，交给数据读写模块。数据 API 只接收已解析的谓词，不接收 SQL 字符串。组织模块不生成 SQL，也不保存这些策略。

阅读顺序与落地顺序相同。

| 模块 | 文档 | 职责 |
|---|---|---|
| 1. 授权 | [01-授权](01-授权.md) | 按应用、实体、角色和动作登记范围 |
| 2. 谓词 | [02-谓词](02-谓词.md) | 一次请求里把授权和主体事实编成谓词，挂到读写上 |
| 3. 系统调用 | [03-系统调用](03-系统调用.md) | 主体 `0` 只放行工作流超时推进里的写入 |

## 要落地的能力

1. 没有授权时，已登录用户读不到业务行，也不能新建。`platform_admin` 不因为管理组织而自动看见业务数据。
2. 角色可以授成全部行，或按某个部门引用字段限制在本人部门、部门下级、或角色绑定上的部门。
3. 多名角色的范围取并集。这个并集包在用户自己的筛选条件外面，用户写的 `or` 不能放宽范围。
4. 解释器里的读写走同一挂点。工作流超时使用的主体 `0` 不能调用对外的数据 API。

## 和其他模块的边界

本模块拥有平台表 `pm_*`。策略引用已经 `active` 的 `entityCode` 和字段编码，不写入数据模型目录。

主体事实在一次请求内向组织模块读取一次，不放进业务事务里加锁。部门闭包只读。本模块不修改 `org_*`。

管理本模块的写接口只认 `platform_admin`，判定方式与组织模块相同：看未结束绑定，不把这次判定再交给本模块，避免循环。

待办的同意和退回仍只认办理人。扩展路由仍只要求已登录。确认、作废这类动作的许可第一期不在这里配置，领域函数自行读取主体事实。

## 第一期不做

按字段或导航拆开的写权限、记录负责人、团队、按条件共享、临时授权、扩展路由上的动作许可。第一期某动作一旦授予，该实体全部 `active` 字段和导航都按该动作放行。未知字段仍由数据读写返回 400。

## 第一期做完的标准

- 未授权时，列表为空，按 id 读取返回 404，新建返回 403。
- `dept_leader` 授成部门树之后，能读到下级部门的行，读不到同级部门的行。
- 筛选条件里用 `or` 写另一个部门的值，不能把范围外的行带出来。
- 解释器 `Query` 与 HTTP `:query` 的范围相同。
- 不带工作流标记的主体 `0` 调用数据 API 返回 403。超时推进里的 `write` 可以写下它声明的字段。
