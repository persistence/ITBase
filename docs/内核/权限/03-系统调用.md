# 系统调用

职责：规定主体 `0` 在数据读写挂点上的放行范围。`0` 不是 `org_user` 的 id，主体事实对它没有部门，也没有角色。

不负责：工作流何时使用 `0`。超时推进才使用它，见 [推进](../工作流/04-推进.md)。变更消费沿用变更行上的 `actor_id`，那个主体按 [谓词](02-谓词.md) 普通判定。

## 1. 标记

数据读写进入挂点时除了用户 id，还带一个来源：

| 来源 | 含义 |
|---|---|
| `user` | 当前会话里的用户。id 必须是正整数 |
| `workflow` | 工作流超时推进里的 `write` 或 `call`。id 为 `0` |

对外的 `/api/v1/data` 只能是 `user`。请求体里不能声明自己是 `workflow`。解释器路径上的来源由宿主注入，领域函数不能改。

`user` 且 id 为 `0`，或来源不是上表之一：直接 403。

## 2. workflow 来源

来源为 `workflow` 时，不读取角色授权，也不套用部门谓词。放行限于这次推进已经打开的那一张业务行：

- 实体编码和记录 id 与当前流程实例一致。
- 动作是 `read` 或 `update`。不能 `create` 另一张实体，也不能 `delete`。
- `update` 的字段必须出现在当前 `write` 节点的 `write_json` 里，或出现在该 `call` 节点这次实际提交的字段里。多出来的字段返回 403。

`call` 里若要新建其他实体的行，不能靠主体 `0`。该函数应在有登录用户的办理请求里执行，或改由变更上的 `actor_id` 执行。超时路径只做定义里已经声明的回写。

来源为 `workflow` 的写入，变更历史里的 `actor_id` 仍是 `0`，`source` 按数据读写原来的规则记为 `system` 或 `domain`。

## 3. 本模块完成标准

- 不带会话调用 `/api/v1/data` 返回 401。会话有效但把用户 id 伪造成 `0` 无法表达，挂点看不到这种请求。
- 宿主在非超时路径上以 `0` 调用读写，返回 403。
- 超时推进更新实例所在的那一行、且字段都在 `write_json` 里时，写入成功。同一调用再改另一个字段返回 403，该行不变。
