# 授权

职责：登记「哪个角色，对哪个应用里的哪张实体，可以做哪个动作，行范围怎么划」。

不负责：把规则编译成某一次请求的谓词（见 [谓词](02-谓词.md)）；角色和绑定本身（见 [组织角色](../用户与组织/03-组织角色.md)）。

依赖：实体和字段已经是该应用内 `active` 的目录对象。角色编码必须是 `org_role` 里现存的编码，停用的角色不能新建授权。

接口前缀 `/api/v1/pm`。写操作要求 `platform_admin`。已登录用户可以读取自己拥有的角色在各实体上的动作，不能读取其他角色的授权。

## 1. pm_grant

```sql
CREATE TABLE pm_grant (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '授权主键',
  app_id      BIGINT UNSIGNED NOT NULL COMMENT '应用',
  entity_code VARCHAR(40)     NOT NULL COMMENT '实体编码',
  role_code   VARCHAR(40)     NOT NULL COMMENT 'org_role.code',
  action      VARCHAR(16)     NOT NULL COMMENT 'read、create、update、delete',
  scope       VARCHAR(16)     NOT NULL COMMENT 'all、dept_self、dept_tree',
  dept_field  VARCHAR(40)     NULL COMMENT '部门引用字段。scope 为 all 时必须为空',
  row_version BIGINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '乐观锁',
  created_at  DATETIME(3)     NOT NULL COMMENT '创建时间，UTC',
  created_by  BIGINT UNSIGNED NOT NULL COMMENT '创建人',
  updated_at  DATETIME(3)     NOT NULL COMMENT '最后修改时间，UTC',
  updated_by  BIGINT UNSIGNED NOT NULL COMMENT '最后修改人',
  PRIMARY KEY (id),
  UNIQUE KEY uk_pm_grant (app_id, entity_code, role_code, action)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '角色对实体的动作与行范围';
```

同一角色、同一实体、同一动作只有一行。要改范围时带 `rowVersion` 更新，不插入第二行。

| scope | 行范围 |
|---|---|
| `all` | 该应用这张实体的全部行。`dept_field` 必须为空 |
| `dept_self` | `dept_field` 的值落在允许的部门 id 集合里 |
| `dept_tree` | `dept_field` 的值落在这些部门自身及其下级 |

`dept_field` 必须是该实体上 `active` 的字段，类型为指向 `org` 应用 `department` 实体的 `ref`。组织范围角色和部门范围角色都可以使用这三种 `scope`。允许的部门 id 从哪里来，在 [谓词](02-谓词.md) 里按角色的 `scope` 区分。

删除授权使用单独接口。不提供停用列。角色在组织模块被停用后，主体事实不再返回该角色，已有授权行保留，但不会参与谓词。

## 2. 接口

| 方法与路径 | 作用 |
|---|---|
| `POST /api/v1/pm/apps/{appCode}/grants` | 新建一行。请求给出 `entityCode`、`roleCode`、`action`、`scope`、可选 `deptField` |
| `PATCH /api/v1/pm/apps/{appCode}/grants/{id}` | 修改 `scope` 和 `deptField`。带 `rowVersion`。动作和角色不在请求体里 |
| `DELETE /api/v1/pm/apps/{appCode}/grants/{id}` | 删除一行 |
| `POST /api/v1/pm/apps/{appCode}/grants:query` | 按实体、角色、动作查询 |

JSON 里的 id 和 `rowVersion` 用十进制字符串。

## 3. 错误

| HTTP | 何时 |
|---|---|
| 400 | 动作或 `scope` 不合法；`all` 却带了部门字段；非 `all` 却没带部门字段；id 用了 JSON 数字 |
| 401 | 未登录 |
| 403 | 非 `platform_admin` 写授权；读取与自己角色无关的授权 |
| 404 | 应用、实体、字段、角色或授权行不存在；字段不是指向部门的 `ref`；实体或字段不是 `active` |
| 409 | 同一角色、实体、动作已有授权；`rowVersion` 不匹配；角色已停用 |

## 4. 本模块完成标准

- 能给 `dept_leader` 对 `leave` 实体授予 `read` 和 `update`，`scope` 为 `dept_tree`，`dept_field` 为 `dept`。
- 把 `scope` 改成 `all` 时必须同时清空 `dept_field`，否则 400。
- 两个请求用同一个 `rowVersion` 修改同一行时，只有一个成功。
