# 流程定义

职责：在一个应用内保存流程的草稿和已发布版本。版本里有节点和边。审批流是人工节点使用 `approve` 与 `reject` 两条边的流程。

不负责：办理人在运行时算成哪些用户（见 [办理人](02-办理人.md)）；实例和待办（见 [实例与待办](03-实例与待办.md)）；何时自动发起（见 [推进](04-推进.md)）。

依赖：实体、字段在目录中为 `active`。`call` 节点指向的领域函数在该模块的已发布修订里存在，签名与 [解释器运行时](../数据模型/07-解释器运行时.md) 的领域函数相同。

接口前缀 `/api/v1/wf`。写定义要求 `platform_admin`。已登录用户可以读取已发布流程的编码和显示名。

## 1. 流程与版本

```sql
CREATE TABLE wf_proc (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '流程主键',
  app_id       BIGINT UNSIGNED NOT NULL COMMENT '所属应用',
  code         VARCHAR(40)     NOT NULL COMMENT '流程编码。创建后不改',
  title        VARCHAR(80)     NOT NULL COMMENT '显示名',
  entity_code  VARCHAR(40)     NOT NULL COMMENT '绑定的实体编码。创建后不改',
  status       VARCHAR(16)     NOT NULL COMMENT 'active、disabled',
  row_version  BIGINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '乐观锁',
  created_at   DATETIME(3)     NOT NULL COMMENT '创建时间，UTC',
  created_by   BIGINT UNSIGNED NOT NULL COMMENT '创建人',
  updated_at   DATETIME(3)     NOT NULL COMMENT '最后修改时间，UTC',
  updated_by   BIGINT UNSIGNED NOT NULL COMMENT '最后修改人',
  PRIMARY KEY (id),
  UNIQUE KEY uk_wf_proc (app_id, code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '流程。运行中的实例不因停用而中断';

CREATE TABLE wf_ver (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '版本主键',
  proc_id      BIGINT UNSIGNED NOT NULL COMMENT 'wf_proc.id',
  version      INT UNSIGNED    NOT NULL COMMENT '版本号，从 1 递增。草稿取已发布最大号加 1',
  phase        VARCHAR(16)     NOT NULL COMMENT 'draft、published、retired',
  published_at DATETIME(3)     NULL COMMENT '变为 published 的时间，UTC',
  phase_slot   VARCHAR(64) GENERATED ALWAYS AS (
                 CASE
                   WHEN phase IN ('draft', 'published') THEN CONCAT(phase, ':', proc_id)
                   ELSE NULL
                 END
               ) STORED COMMENT '每个流程的 draft 与 published 各一槽',
  PRIMARY KEY (id),
  UNIQUE KEY uk_wf_ver (proc_id, version),
  UNIQUE KEY uk_wf_ver_phase_slot (phase_slot)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '流程版本。实例绑定启动时的版本';
```

编码符合 `^[a-z][a-z0-9_]{0,39}$`。`entity_code` 必须是该应用内 `active` 的实体。停用流程只拒绝新的发起和触发，已经 `running` 的实例继续走原版本。

一个流程同时只有一份草稿和一份已发布版本。发布事务里先把原 `published` 改为 `retired`，再把草稿改为 `published`。发布后节点和边不再更新。要修改时从当前已发布版本复制出新草稿。

## 2. 节点与边

```sql
CREATE TABLE wf_node (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '节点主键',
  ver_id      BIGINT UNSIGNED NOT NULL COMMENT 'wf_ver.id',
  code        VARCHAR(40)     NOT NULL COMMENT '节点编码。版本内唯一',
  kind        VARCHAR(16)     NOT NULL COMMENT 'start、human、write、call、end',
  title       VARCHAR(80)     NOT NULL COMMENT '显示名',
  timeout_min INT UNSIGNED    NULL COMMENT '仅 human。空表示不超时',
  module_code VARCHAR(40)     NULL COMMENT '仅 call。已发布模块编码',
  func_name   VARCHAR(80)     NULL COMMENT '仅 call。领域包导出函数名',
  write_json  JSON            NULL COMMENT '仅 write。字段编码到字面值',
  end_status  VARCHAR(16)     NULL COMMENT '仅 end。completed 或 rejected',
  PRIMARY KEY (id),
  UNIQUE KEY uk_wf_node (ver_id, code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '流程节点';

CREATE TABLE wf_edge (
  id         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '边主键',
  ver_id     BIGINT UNSIGNED NOT NULL COMMENT 'wf_ver.id',
  from_code  VARCHAR(40)     NOT NULL COMMENT '起点节点编码',
  outcome    VARCHAR(16)     NOT NULL COMMENT 'ok、approve、reject、timeout',
  to_code    VARCHAR(40)     NOT NULL COMMENT '终点节点编码',
  PRIMARY KEY (id),
  UNIQUE KEY uk_wf_edge (ver_id, from_code, outcome)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '流程边。结果决定下一节点';
```

| 节点 | 必有的出边 | 内容 |
|---|---|---|
| `start` | `ok` | 每个版本恰好一个。没有入边 |
| `human` | `approve`、`reject` | `timeout` 可有可无。办理人见 [办理人](02-办理人.md) |
| `write` | `ok` | `write_json` 是对象。键是字段编码，值是该类型的字面量。`decimal` 与 `bigint` 用十进制字符串 |
| `call` | `ok` | `func_name` 匹配 `^[A-Z][A-Za-z0-9]{0,60}$` |
| `end` | 无 | `end_status` 为 `completed` 或 `rejected` |

`reject` 边可以指回更早的人工节点。除此之外，从 `start` 沿 `ok`、`approve`、`timeout` 必须是无环的。`call` 与 `write` 的 `ok` 边不能指回自己。发布时拒绝无法到达的节点，以及无法到达任一 `end` 的路径。

`write_json` 的字段必须是该实体上 `active` 的标量或选项。若本版本有启动触发，写节点的字面值不能刚好满足同一条触发条件，避免推进把自己再次启动。触发条件见 [推进](04-推进.md)。

`call` 在发布时检查：该模块存在 `published` 修订，且导出函数能断言成领域函数签名。

## 3. 接口

| 方法与路径 | 作用 |
|---|---|
| `POST /api/v1/wf/apps/{appCode}/procs` | 创建流程和空草稿。请求给出 `code`、`title`、`entityCode` |
| `PUT /api/v1/wf/apps/{appCode}/procs/{code}/draft` | 整表替换草稿的节点、边和办理人。带 `rowVersion` |
| `POST /api/v1/wf/apps/{appCode}/procs/{code}:publish` | 检查并发布草稿 |
| `POST /api/v1/wf/apps/{appCode}/procs/{code}:disable` | `active → disabled` |
| `POST /api/v1/wf/apps/{appCode}/procs/{code}:enable` | `disabled → active` |
| `GET /api/v1/wf/apps/{appCode}/procs/{code}` | 读取流程和当前已发布版本的节点与边 |

`PUT` 的 `rowVersion` 不匹配返回 409。没有草稿时，发布接口先按 [用户与组织](../用户与组织/README.md) 里同一套「先取已发布再复制」的做法生成草稿；本接口在复制时对 `wf_proc` 行加锁。两个并发的首次保存只留下一份 `draft`。

## 4. 错误

| HTTP | 何时 |
|---|---|
| 400 | 编码、节点种类、边的 `outcome` 不合法；`write_json` 不是对象 |
| 401 | 未登录 |
| 403 | 非 `platform_admin` 写定义 |
| 404 | 应用或流程不存在；实体不是该应用的 `active` 实体 |
| 409 | 编码冲突；`rowVersion` 不匹配；并发草稿 |
| 422 | 发布检查失败。正文带节点编码和原因：缺边、环、字段未生效、领域函数不在已发布修订中、写节点满足自身启动条件 |

## 5. 本模块完成标准

- 能创建并发布一张流程：`start` → 人工节点 → `write` → `end`。退回边进入另一个 `end`，`end_status` 为 `rejected`。
- 发布之后修改已发布节点的请求不存在。新草稿从已发布版本复制，原版本继续供已启动的实例使用。
- 领域函数尚未发布时，`:publish` 返回 422，已发布版本不变。
- 停用后不能再发起。停用前已经运行的实例仍可同意或退回。
