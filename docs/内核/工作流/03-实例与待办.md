# 实例与待办

职责：对一条业务记录启动流程实例，把当前人工节点变成待办，并接受办理人的同意或退回。

不负责：版本内容（见 [流程定义](01-流程定义.md)）；办理人如何解析（见 [办理人](02-办理人.md)）；领域函数和超时（见 [推进](04-推进.md)）。

依赖：业务行必须能被当前用户读到。读挂点拒绝时不创建实例。

接口前缀 `/api/v1/wf`。发起和办理要求已登录。查询待办只返回当前用户自己的行。`platform_admin` 可以按实例 id 读取任意实例，用于排查。

## 1. 表

```sql
CREATE TABLE wf_instance (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '实例主键',
  app_id       BIGINT UNSIGNED NOT NULL COMMENT '应用',
  proc_id      BIGINT UNSIGNED NOT NULL COMMENT 'wf_proc.id',
  ver_id       BIGINT UNSIGNED NOT NULL COMMENT '启动时的 wf_ver.id',
  record_id    BIGINT UNSIGNED NOT NULL COMMENT '业务行 id',
  status       VARCHAR(16)     NOT NULL COMMENT 'running、completed、rejected、error',
  node_code    VARCHAR(40)     NULL COMMENT '当前所在节点。结束后为空',
  error_code   VARCHAR(40)     NULL COMMENT 'error 时的代码',
  started_by   BIGINT UNSIGNED NOT NULL COMMENT '发起人用户 id',
  started_at   DATETIME(3)     NOT NULL COMMENT '发起时间，UTC',
  updated_at   DATETIME(3)     NOT NULL COMMENT '最近推进时间，UTC',
  open_token   BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT 'running 为 0。结束后写成自己的 id',
  PRIMARY KEY (id),
  UNIQUE KEY uk_wf_instance_open (proc_id, record_id, open_token),
  KEY idx_wf_instance_record (app_id, record_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '流程实例。同一流程同一记录同时只有一个 running';

CREATE TABLE wf_task (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '待办主键',
  instance_id BIGINT UNSIGNED NOT NULL COMMENT 'wf_instance.id',
  node_code   VARCHAR(40)     NOT NULL COMMENT '人工节点编码',
  user_id     BIGINT UNSIGNED NOT NULL COMMENT '办理人',
  status      VARCHAR(16)     NOT NULL COMMENT 'open、done、cancelled',
  outcome     VARCHAR(16)     NULL COMMENT 'done 时为 approve 或 reject',
  comment     VARCHAR(500)    NULL COMMENT '办理意见。可空',
  due_at      DATETIME(3)     NULL COMMENT '超时时刻，UTC。无超时为空',
  row_version BIGINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '乐观锁',
  created_at  DATETIME(3)     NOT NULL COMMENT '创建时间，UTC',
  acted_at    DATETIME(3)     NULL COMMENT '办理时间，UTC',
  open_token  BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT 'open 为 0。结束后写成自己的 id',
  PRIMARY KEY (id),
  UNIQUE KEY uk_wf_task_open (instance_id, node_code, user_id, open_token),
  KEY idx_wf_task_user (user_id, status, id),
  KEY idx_wf_task_due (status, due_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT '待办';
```

`open_token` 的用法与组织模块的任职相同：未结束为 `0`，结束后写成该行自己的 id。因此同一流程、同一记录可以在结束后再次发起。

实例进入 `completed` 或 `rejected` 时写下对应状态，`node_code` 清空，`open_token` 写成实例 id。进入 `error` 时保留 `node_code`，同样结束 `open_token`，第一期不从 `error` 自动重试。业务行保持推进失败之前的值。

待办从 `open` 变为 `done` 或 `cancelled` 时，`open_token` 写成待办 id。`due_at` 在创建时按节点的 `timeout_min` 加上创建时间。没有超时配置则为空。

JSON 里的 id、`recordId`、`rowVersion` 用十进制字符串。

## 2. 发起

`POST /api/v1/wf/apps/{appCode}/procs/{procCode}:start`

```json
{ "recordId": "41" }
```

条件：

1. 流程 `status` 为 `active`，且存在 `published` 版本。
2. 当前用户对 `entity_code` + `recordId` 的读挂点放行。记录不存在为 404。
3. 不存在 `open_token = 0` 的实例。已存在则 409。

成功时在一个事务里插入 `running` 实例，`started_by` 为当前用户，`node_code` 为 `start`，然后按 [推进](04-推进.md) 沿 `ok` 边走到第一个需要等待的人工节点，或走到结束。事务失败则不留下实例。

## 3. 办理

| 方法与路径 | 作用 |
|---|---|
| `POST /api/v1/wf/tasks:query` | 当前用户的待办。`status` 默认 `open` |
| `GET /api/v1/wf/tasks/{id}` | 读取一条待办。不是办理人也不是 `platform_admin` 则 403 |
| `POST /api/v1/wf/tasks/{id}:approve` | 同意。正文可带 `comment` 和 `rowVersion` |
| `POST /api/v1/wf/tasks/{id}:reject` | 退回。正文相同 |
| `GET /api/v1/wf/instances/{id}` | 读取实例、当前节点和它的待办 |

同意和退回只接受 `status = open` 且 `user_id` 为当前用户的待办。`rowVersion` 不匹配返回 409。办理人用户状态不是 `active` 时返回 403。

在一个事务里：

1. 锁住实例和这条待办。
2. 把这条待办标为 `done`，写下 `outcome` 和 `acted_at`。
3. 把同一实例、同一节点上其余 `open` 待办标为 `cancelled`。
4. 按 `approve` 或 `reject` 边推进。推进中的 `write` 与 `call` 加入同一事务。失败则整单回滚，待办仍为 `open`。

两人同时办理时，后提交的一方等到锁，看到待办已不是 `open`，返回 409。

## 4. 错误

| HTTP | 何时 |
|---|---|
| 400 | `recordId` 或 `rowVersion` 用了 JSON 数字；意见超过 500 字 |
| 401 | 未登录 |
| 403 | 读挂点拒绝；办理人不是当前用户；办理人已停用或离职 |
| 404 | 流程、记录、待办或实例不存在 |
| 409 | 已有运行中实例；`rowVersion` 不匹配；待办已结束 |
| 422 | 下一人工节点解析不出办理人；`write` 或领域函数返回业务错误。人工请求回滚 |

## 5. 本模块完成标准

- 发起后实例为 `running`，办理人能在自己的待办列表里看到它。另一名用户的列表里没有这条。
- 同意之后实例为 `completed` 或停在下一人工节点。退回之后若边指向 `end_status = rejected` 的结束节点，实例为 `rejected`。
- 同一 `recordId` 在实例结束前再次发起返回 409。结束后可以再发起，新实例使用当时的已发布版本。
- 两个办理请求使用同一个 `rowVersion` 时只有一个成功。
